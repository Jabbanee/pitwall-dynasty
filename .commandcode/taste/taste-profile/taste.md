# Taste Profile
- On large build tasks, work fully autonomously: make sensible product/engineering decisions yourself, don't ask implementation questions unless progress is literally impossible, and don't stop at scaffolds, mockups, architecture docs, or partial prototypes — implement the whole thing end-to-end. Confidence: 0.95
- Working software beats planning: when choosing between another page of planning and making the thing more functional/playable, choose function; reach a usable loop early and keep improving. If a feature is too large, ship the strongest simplified working version rather than omitting it. Placeholder-only delivery ("Coming Soon", "TODO", "Not Implemented" for core features) is unacceptable. Confidence: 0.9
- Determinism first in any simulation: thread an explicit seeded RNG through authoritative logic, ban unseeded `Math.random` there, and persist seed + simulation version + rules hash so identical inputs reproduce identical outcomes. Confidence: 0.9
- Authoritative/headless separation: simulation runs independently of rendering, frame rate, camera, or UI loops; clients consume output and never determine outcomes. Confidence: 0.85
- Keep dependencies minimal — avoid unnecessary framework complexity (plain TS was acceptable where a UI framework would be typical); use strong typing, organize code by domain boundaries, avoid giant god files, document unusual algorithms. Confidence: 0.85
- Ship tests for core logic (reproducibility/same-seed-same-result, scoring math, save/load round-trips, invalid input/mod reference rejection) plus developer utilities (batch simulation with aggregate stats, instant sim, skip timers, reset save) kept clearly separate from normal gameplay. Confidence: 0.85
- Fail gracefully: handle corrupt saves, invalid mods, disconnects, and timeouts with actionable user-facing errors instead of crashes. Confidence: 0.8
- Build original fictional universes — no real-world trademarks, driver/team names, liveries, logos, or obvious near-parodies; use stable IDs (never display names) as authoritative identifiers so content stays moddable, backed by a versioned manifest format with validation. Confidence: 0.8
- End a build like a QA engineer: run all tests/build/typecheck, fix errors rather than merely reporting them, remove console errors, then start the dev server, navigate to the actual playable app in the browser (not a blank landing page), and leave it running at the exact point where the user can immediately begin playing/testing. Confidence: 0.9
- Close out with an honest summary: what was implemented, key architectural decisions, test/build results, known limitations, and files worth inspecting — never claim features exist if they don't. Confidence: 0.9
