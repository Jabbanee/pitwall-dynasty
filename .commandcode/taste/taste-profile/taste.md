# Taste Profile
- On large build tasks, work fully autonomously: make sensible product/engineering decisions yourself, don't ask implementation questions unless progress is literally impossible, and don't stop at scaffolds, mockups, architecture docs, or partial prototypes — implement the whole thing end-to-end. Confidence: 0.95
- Working software beats planning: when choosing between another page of planning and making the thing more functional/playable, choose function; reach a usable loop early and keep improving. If a feature is too large, ship the strongest simplified working version rather than omitting it. Placeholder-only delivery ("Coming Soon", "TODO", "Not Implemented" for core features) is unacceptable. Confidence: 0.9
- Determinism first in any simulation: thread an explicit seeded RNG through authoritative logic, ban unseeded `Math.random` there, and persist seed + simulation version + rules hash so identical inputs reproduce identical outcomes; for interactive/live sims, capture immutable pre-event packages plus an append-only ordered command log so outcomes replay deterministically (with tests proving it). Confidence: 0.95
- Authoritative/headless separation: simulation runs independently of rendering, frame rate, camera, or UI loops; clients consume output and never determine outcomes. In real multiplayer this means an actual server transport (WebSocket-class) owning all state — clients only send actions and receive reveal-safe snapshots — and synchronization verified with two real browser clients before ever claiming multiplayer works. Confidence: 0.9
- Keep dependencies minimal — avoid unnecessary framework complexity (plain TS was acceptable where a UI framework would be typical); use strong typing, organize code by domain boundaries, avoid giant god files, document unusual algorithms. Confidence: 0.85
- Ship tests for core logic (reproducibility/same-seed-same-result, scoring math, save/load round-trips, invalid input/mod reference rejection) plus developer utilities (batch simulation with aggregate stats, instant sim, skip timers, reset save) kept clearly separate from normal gameplay. Confidence: 0.85
- Fail gracefully: handle corrupt saves, invalid mods, disconnects, and timeouts with actionable user-facing errors instead of crashes. Confidence: 0.8
- Build original fictional universes — no real-world trademarks, driver/team names, liveries, logos, or obvious near-parodies; use stable IDs (never display names) as authoritative identifiers so content stays moddable, backed by a versioned manifest format with validation. Confidence: 0.8
- End a build like a QA engineer: run all tests/build/typecheck, fix errors rather than merely reporting them, remove console errors, then start the dev server, navigate to the actual playable app in the browser (not a blank landing page), and leave it running at the exact point where the user can immediately begin playing/testing. Confidence: 0.9
- Screenshots are first-class QA artifacts, not throwaways: capture them into a versioned `docs/testing/screenshots/<phase>/` directory, commit them to git (never leave them in temp Playwright dirs, never delete before commit), and maintain a per-screenshot `VISUAL_QA.md` manifest recording filename / screen / what it verifies / expected behavior / PASS-FAIL. Also actually open and inspect the PNGs — look for broken layout, clipping, tiny text, blank canvas, missing cars, overlapping HUD, debug garbage — and re-capture replacements until acceptable. Confidence: 0.9
- Close out with an honest summary: what was implemented, key architectural decisions, test/build results, known limitations, and files worth inspecting — never claim features exist if they don't. Confidence: 0.9
- Evolving an existing working codebase: checkpoint before changing anything (run tests/build, audit reusable systems, commit a safe baseline), refactor only what the target design requires, regression-test continuously so old features keep passing, and commit incrementally with meaningful conventional-style messages per feature stage (`feat(scope): …`) — never one giant final commit. Confidence: 0.9
- Dynamic entity/relationship state is session-scoped: each championship/session starts mutable state (morale, trust, grudges, history) from a clean baseline in isolated stores; global base/static content data is never accidentally mutated. Confidence: 0.8
- No unexplained UI states: every disabled/unavailable action carries its reason (prohibited by rules, resource missing, decision point passed), risky/probabilistic actions surface expected likelihoods with a reason breakdown, and cause-and-effect feedback follows every action — hidden arbitrary logic is unacceptable. Confidence: 0.8
- Game rules, eras, and tuning live in centralized data-driven modules that the UI queries (regulations by year, points tables, formats), never hardcoded constants scattered across screens. Confidence: 0.75
